"旧框架装不下新能力:LLM 不是更聪明的意图匹配器。"

传统车载语音的交互契约是「用户说出接近指令格式的话 → 系统匹配意图 → 执行或播报失败」。LLM 打破了契约的两端:输入端,用户可以说「我有点冷」这类没有标准答案的话;执行端,Agent 可以规划多步操作、调用多个工具、主动建议。但多数量产助手把 LLM 塞回旧框架——听懂了更多话,交互上仍是黑盒执行。

当座舱助手从「命令执行器」变成「有能力但会出错的 Agent」,设计要回答的不再是「怎么让用户学会说对的话」,而是「怎么让人和一个不完全可靠的智能体在驾驶场景下安全地协作」。

五个命题的设计答案

把大问题拆成五个可设计、可检验的命题——每个命题都有明确的设计产出,并在 demo 中可交互验证。

01

不确定性表达

模型没把握时,UI 怎么办?

置信度不展示数值,转译成交互形态——用户不需要知道「78% 确定」,需要知道「它要不要我确认」。

高置信 → 直接执行 + 回显;中置信 → 先复述意图再执行,留出打断窗口;低置信 → 转确认式,给 2-3 个候选。涉及安全与不可逆操作时,中置信也降为确认式——宁可问,不可猜。

降级不是报错,是换一种问法——语气与视觉上不制造「失败感」。

02

流式响应

token 逐字吐出,驾驶场景怎么呈现?

流式是技术事实,不是交互形态。驾驶场景下「逐字蹦」对屏显是噪音、对语音不可行:

语音走句子级缓冲——攒满语义完整的句子才开口,首句要快;屏显走块级更新——按语义块整块出现,驾驶中瞥到的永远是完整可读的信息;等待要可解释——「正在查充电桩…」而不是抽象转圈;随时可打断,打断后保留上下文。

03

Agent 授权边界

它能直接做什么?错了怎么办?

按「错了的代价」分级,而不是按「技术上能不能做」分级:

直接执行(可逆、纠错成本≈0):温度、音量 → 执行 + 回显 + 一键撤销;
口头确认(可逆但打断成本高):导航改道、发消息 → 复述意图,口头确认即执行;
强确认(不可逆 / 涉钱 / 涉行车安全):付款等 → 必须屏幕或实体键确认,语音不可确认,且不可降级。

边界要可感知(授权总览)、可调整(分级用户可调,底线除外)、可追溯(行为流水)。与控制中心案例的「Agent 行为可见层」直接咬合。

04

多模态与驾驶注意力

信息往哪放?

按注意力预算分配通道(参考 NHTSA 分心指南,单次瞥视 <2s):语音说结论,不播列表;屏显放可瞥视的结构化卡片,行车中永远不需要滚动;停车态才解锁长列表与多轮比价;Agent 行车中的主动发言仅限安全相关。

通道分配矩阵 + 行车/停车两态 · 图片占位
05

失败降级

失败体验是 AI 产品的第一体验

每种失败都有明确的「下一步」,用户永远不站在死胡同里:断网 → 显式声明 + 本地车控可用;听错 → 转确认式;事实类回答 → 标注来源,查不到就说查不到;执行失败 → 回显原因 + 重试/换方式/算了。

手动兜底是安全网,也是信任机制:任何时刻一步退回手动。用户知道随时能收回控制权,才敢把控制权交出去。
