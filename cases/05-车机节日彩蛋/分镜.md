# 案例⑤ PDF 分镜（页面级排版方案）

> 依据 [排版规范.md](../../排版规范.md)。骨架、三层视觉层级、配色、字号全部沿用全书统一规则，这里只定**这个案例每一页解决什么问题**。
> 每页给出 **L1 结论（大字）/ L2 解释（中字）/ L3 证据（图表）**，一页只回答一个问题。

## 篇幅：建议 8 页（原预算 4–5，外部建议 10–14）

**取 8 页的理由**：

- 4–5 页装不下"一页一个问题"的节奏，四个决策必然被压回表格堆——那正好滑回 v1 的规范说明书。
- 10–14 页对这个案例撑不住，原因不在内容，在**归属**：那个页数依赖"Final Experience 大量 UI 大图"这一页，而我的角色限定在前期规划，**视觉动效不是我的产出**。硬凑等于踩红线。
- 案例⑤ 是**方法型短案例**，任务是给主力①② 做侧证。它比主力还长，全书重心就歪了。

**伸缩办法**：要压到 5 页，合并 P4+P5、P7+P8；要放到 11 页，把四个决策从一页两个拆成一页一个（P5 拆 2 页）、关键场景一页一个（P7 拆 3 页）。**不靠加 UI 图注水。**

## P1｜Cover

| 层 | 内容 |
|---|---|
| L1 | **在驾驶安全优先的车机里，情绪该怎么出现？** |
| L2 | 为节日彩蛋建立一套「可发现、可互动、但不打扰」的系统行为框架 |
| L3 | 信息条：竞品研究 · 系统边界定义 · 交互规范（前期规划）｜某新能源品牌车机 HMI｜2025 |

视觉：**图 2b 四级仲裁决策树的局部特写**，压暗做背景。
⚠️ 不用彩蛋动画效果图当封面——那是别人的产出，且会把案例定位成"我做了个可爱彩蛋"。

## P2｜Overview

一页回答：为什么做？我负责什么？最终解决什么？

| 层 | 内容 |
|---|---|
| L1 | 表面是做一个节日彩蛋，实际是**给一个纯情绪元素定义系统行为** |
| L2 | 当它被放进一块随时可能被安全事件抢占的屏幕，系统该怎么替它做决定 |
| L3 | 角色边界明写：我负责竞品研究、系统边界、交互规范；**视觉动效与量产落地不是我的产出** |

角色边界放在第 2 页而不是藏在末尾——**主动交代边界是加分项，被问出来才是减分项。**

## P3｜The Challenge

这一页负责钩住面试官，**信息量要少，气势要足**。

| 层 | 内容 |
|---|---|
| L1 | **How can a car surprise users without distracting them?** |
| L2 | 手机彩蛋成立的三个前提，在车机里全部不成立 |
| L3 | 三组矛盾左对齐排开：`Emotion × Safety`　`Discovery × Interruption`　`Interaction × System` |

正文里那张"手机前提 / 车机现实"对照表放这页做 L3，**别放满**，留白比内容重要。

## P4｜Research → Opportunity

不要六张竞品截图平铺。收敛结构是：**6 products → 3 patterns → 1 opportunity**。

| 层 | 内容 |
|---|---|
| L1 | **大多数产品在回答"怎么增加玩法"，没人回答"它该怎么自然地出现和退场"** |
| L2 | 玩法密度在涨，注意力成本却没被当成需要管理的变量 |
| L3 | 图 1 竞品矩阵（6 款 × 3 维度）+ 三种模式的收敛线 |

页脚小字保留采样限定：*结论只适用于当时选取的样本与版本。*

## P5｜Design Opportunity + Principles

**整个案例的观点页。** 上半页给主张，下半页给四条原则。

| 层 | 内容 |
|---|---|
| L1 | **From "playable Easter eggs" to "discoverable moments".**　不要让用户"去玩"彩蛋，要让用户"撞见"它 |
| L2 | Surprise ＞ Interruption　｜　Passive discovery ＞ Active engagement |
| L3 | 四条原则，每条三行：`Principle` / `Why` / `Implication`——原则必须带 Implication，否则是口号 |

顺带把用户视角的两条路径放这页做小图：默认路径「看见 → 会心一笑 → 不操作」vs 互动路径。
⚠️ 必须标注"设计假设，本阶段无用户测试"，字号 9–11 但**不能省**。

## P6｜System Exploration

**最加分的一页**，因为它证明规则是我推出来的，不是抄来的。

| 层 | 内容 |
|---|---|
| L1 | **Where should the Easter egg live?** |
| L2 | 三个候选：A 覆盖 Dock / B 独立全屏 / C 边缘挂件 |
| L3 | 三栏对照：优点 / 排除理由，C 用 Accent `#2563eb` 标为 Selected |

同页放决策 04 的三选一（跟随迁移 / 原桌面续渲染 / 停渲染但状态走完）。
⚠️ **方案 B 是否真实评估过待你确认**——没确认前这页就做 A→C 二选一，一样成立。

## P7｜Interaction Model —— 视觉 Hero

**全案分量最重的一页，给整页。**

| 层 | 内容 |
|---|---|
| L1 | **我没有采用「打断／不打断」的二元规则，而是建立了四级状态仲裁模型** |
| L2 | 语音播报和 SOS 都算"打断"，但一个只需让出注意力、之后可恢复，另一个必须立即清除且不许续播 |
| L3 | 图 2b 决策树：系统事件 → 普通更新／注意力冲突／安全事件 → 继续／弱化・暂停／终止 |

配色按语义：终止用 `#dc2626`，弱化/暂停用 `#b45309`，继续用灰。
**这页做成系统决策模型，不做成普通表格**——四行表格换不来这个印象。

## P8｜Scenarios + Outcome + Reflection

三个场景横排（`× Voice` / `× Navigation` / `× Safety`），每个走同一条时间轴：
`System event → 仲裁判定 → 界面行为 → 恢复`

然后收在 Outcome 与 Reflection：

| 层 | 内容 |
|---|---|
| L1 | **系统行为从「每个节日单独讨论」变成「归入四类响应之一」** |
| L2 | 安全优先级、跨桌面归属、多节日冲突，在视觉阶段开始前就已有唯一答案 |
| L3 | 反思：交互设计不只是定义**用户可以做什么**，也是定义**当用户和系统同时行动时系统该怎么办** |

⚠️ **真实采纳结果待补**（见 [只差你了.md](../../只差你了.md)）。没有就只写"交付了什么 + 消除了哪几类重复讨论"，**不编数字**。

## 这个案例排版上最要防的两件事

1. **不要把规范排得特别漂亮。** 反直觉但关键：规范表格越精致，案例越滑向"设计规范展示"。第 6 节的规范片段在 PDF 里只做 L3 证据，压成小字附在 P8，**不单独占页**。
2. **不要为了"最终效果页"去认领视觉。** 外部建议里的 "10 Final Experience 大图" 这一页，在这个案例里由 **P7 的模型图**顶替。我的最终交付物本来就是规则，不是画面——把规则可视化做到极致，比贴几张不属于我的动效图有说服力得多。
