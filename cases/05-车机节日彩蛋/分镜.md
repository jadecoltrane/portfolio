# 案例⑤ PDF 分镜（页面级排版方案）

> 依据 [排版规范.md](../../排版规范.md)。骨架、三层视觉层级、配色、字号沿用全书统一规则，这里只定**每一页解决什么问题**。
> 每页给出 **L1 结论（大字）/ L2 解释（中字）/ L3 证据（图表）**。

## 篇幅：5 页（2026-08-27 拍板）

案例⑤ 是方法型短案例，任务是给主力①② 做侧证——**它的价值在位置，不在篇幅**。比主力短，读者才知道主线在哪。

5 页的代价要认：**「一页只解决一个问题」在这里做不到严格**，有三页是两个问题合页。这是短案例可以接受的折中，但有一条不让：**P4 仲裁模型必须独占整页**，那是全案唯一的视觉 Hero，压缩它等于把案例最值钱的东西降级成一张表。

篇幅若要再变，见文末「伸缩预案」。

## P1｜Opener（封面 + Overview 合页）

| 层 | 内容 |
|---|---|
| L1 | **在驾驶安全优先的车机里，情绪该怎么出现？** |
| L2 | 表面是做一个节日彩蛋，实际是给一个纯情绪元素定义系统行为——当它被放进一块随时可能被安全事件抢占的屏幕，系统该怎么替它做决定 |
| L3 | 信息条：竞品研究 · 系统边界定义 · 交互规范（前期规划）｜某新能源品牌车机 HMI｜2025<br>**角色边界明写**：视觉动效与量产落地不是我的产出 |

视觉：图 2b 决策树局部特写，压暗做背景。
⚠️ 不用彩蛋效果图开场——那是别人的产出，且会把案例定位成"我做了个可爱彩蛋"。
⚠️ 角色边界放开篇不放末尾：**主动交代是加分项，被追问出来是减分项。**

## P2｜Challenge → Opportunity（问题 + 竞品合页）

上半页给问题，下半页给竞品收敛。**这页信息密度最高，靠留白和左对齐撑住，不要排满。**

| 层 | 内容 |
|---|---|
| L1 | **How can a car surprise users without distracting them?** |
| L2 | 手机彩蛋成立的三个前提在车机里全部不成立；而竞品都在回答"怎么增加玩法"，没人回答"它该怎么自然地出现和退场" |
| L3 | 上：三组矛盾左对齐排开 `Emotion × Safety`　`Discovery × Interruption`　`Interaction × System`<br>下：图 1 竞品矩阵，**6 products → 3 patterns → 1 opportunity** 的收敛线 |

页脚小字保留采样限定：*结论只适用于当时选取的样本与版本。*

## P3｜Opportunity + Exploration（主张 + 取舍合页）

**证明规则是我推出来的，不是抄来的。**

| 层 | 内容 |
|---|---|
| L1 | **From "playable Easter eggs" to "discoverable moments".**　不要让用户"去玩"彩蛋，要让用户"撞见"它 |
| L2 | Surprise ＞ Interruption　｜　Passive discovery ＞ Active engagement |
| L3 | **Where should the Easter egg live?** 载体分配表：全屏壁纸（仅壁纸桌面）与边缘挂件（跨桌面）**同为采用**，覆盖 Dock 排除，星球桌面整体彩蛋化为未纳入范围的提案。两个 Selected 用 Accent `#2563eb` |

四条设计原则压成一行式脚注带过（`Principle → Implication`，省掉 Why），**不单独占页**——原则是支撑，取舍才是看点。
用户视角两条路径做小图：默认路径「看见 → 会心一笑 → 不操作」vs 互动路径。
⚠️ 「设计假设，本阶段无用户测试」字号 9–11 但**不能省**。
⚠️ 这页的看点是**全屏不是被否掉而是被分配到了唯一能容纳它的位置**，别排成普通的三选一排除表。全屏壁纸的视觉非本人产出，页内需带一行角色说明。

## P4｜Interaction Model —— 视觉 Hero（整页，不合并）

| 层 | 内容 |
|---|---|
| L1 | **我没有采用「打断／不打断」的二元规则，而是建立了四级状态仲裁模型** |
| L2 | 语音播报和 SOS 都算"打断"，但一个只需让出注意力、之后可恢复，另一个必须立即清除且不许续播 |
| L3 | 图 2b 决策树：系统事件 → 普通更新／注意力冲突／安全事件 → 继续／弱化・暂停／终止 |

配色按语义：终止 `#dc2626`，弱化/暂停 `#b45309`，继续用灰。
**做成系统决策模型，不做成普通表格。**

## P5｜Scenarios + Outcome + Reflection

三个场景横排（`× Voice` / `× Navigation` / `× Safety`），同一条时间轴：
`System event → 仲裁判定 → 界面行为 → 恢复`

| 层 | 内容 |
|---|---|
| L1 | **系统行为从「每个节日单独讨论」变成「归入四类响应之一」** |
| L2 | 安全优先级、跨桌面归属、多节日冲突，在视觉阶段开始前就已有唯一答案 |
| L3 | 反思：交互设计不只是定义**用户可以做什么**，也是定义**当用户和系统同时行动时系统该怎么办** |

⚠️ 真实采纳结果待补（见 [只差你了.md](../../只差你了.md)）。没有就只写"交付了什么 + 消除了哪几类重复讨论"，**不编数字**。

## 这个案例排版上最要防的两件事

1. **不要把规范排得特别漂亮。** 反直觉但关键：规范表格越精致，案例越滑向"设计规范展示"。规范片段在 PDF 里只做 L3 小字证据。
2. **不要为了"最终效果页"去认领视觉。** 我的最终交付物本来就是规则不是画面——把规则可视化做到极致，比贴几张不属于我的动效图有说服力。

## 伸缩预案

- **回到 8 页**（若案例② 降级为短案例、本案需要顶上第二个系统型案例）：P1 拆成封面 + Overview，P2 拆成 Challenge + Research，P3 拆成 Opportunity+Principles + Exploration，P5 拆成 Scenarios + Outcome。
- **压到 4 页**（若全书超预算）：P2 与 P3 再合，但 **P4 仍不动**。
- **任何情况下都不靠加 UI 图注水。**
