## 第一梯队 · 决定案例成色

### 1. 画「落地示范」改前 / 改后（图 9）—— 最重要
全案唯一的界面级视觉产出，100% 属于你，同时补掉作品集"视觉分量"的短板。
正文 5.x 预填了四个示范对象，**你按手上真能画、且改前问题最明显的来挑**：

| # | 示范对象 | 改前问题 | 改后依据 |
|---|---|---|---|
| 1 | 一个有持续状态的车身控制 | 被建成单次按钮，操作完复位，不知当前开还是关 | 改为开关卡片，生效态持续显示 |
| 2 | 一组多状态切换 | 分段滑块与多模切换混用 | ≤3 等价选项用分段，≤4 带语义用多模 |
| 3 | 一个执行链路长的指令 | 只有加载态，失败/超时空白 | 补失败态 + 原因 + 可重试 |
| 4 | 一个条件受限的功能 | 禁用只灰化，不说原因 | 禁用态带原因与恢复条件 |

**定下选哪几个，我把每张图要画的状态逐条列给你。**

### 2. 画「六个必画状态」完整状态图（图 10）
默认 / 按压 / 生效 / 加载 / 失败 / 禁用，在同一个控件上画满。
这张是状态词表的**验证**——画得出来，规则才算立住。

### 3. 用走查清单做一次自验证 ← 结果证据换成这个
**采纳反馈大概率要不到，那就不等它。** 用交付走查清单的 8 项，回头复查现有功能页的控件定义，得出不合规项分布：

> 复查 N 个功能页 / M 个控件 → 失败态缺失 __ 处、禁用无原因 __ 处、状态仅靠文案或底色 __ 处、同性质功能用了不同控件类型 __ 组

**这是本案例最硬的结果**：可核实、能复现、追问到任何一层都答得上；而且它证明清单真的能查出东西。
提案去向如实写"已反馈，尚无正式采纳结论"即可——规范类提案的常态就是这样，面试官清楚。**不编。**
