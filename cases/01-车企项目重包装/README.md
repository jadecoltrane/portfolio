## 框架

### 1. 背景与我的角色
- 量产车机控制中心的改版迭代与新功能承接;我负责交互设计,主导功能排序与布局
- 角色话术:"加什么功能是产品定义的,**怎么进、放在哪、怎么呈现是我定的**"
- ⚠️ 外包身份不回避也不主动强调,写"作为 UX 设计师深度参与"

### 2. 发现问题
- 结构性矛盾:新功能持续加入 → 一级入口膨胀 → 驾驶中找不到 / 够不着
- 用真实用户反馈锚定问题(脱敏引用)

### 3. 竞品拆解(深化版,现在补做)
- 全部基于公开界面,合法可做;从"布局对比"升级为维度化拆解:
  入口密度 / 常驻 vs 可自定义 / 开关状态可读性 / 驾驶中热区可达性 / 与设置页的层级分工

### 4. 设计决策点(2-3 个)
- **决策 A|排序逻辑**:使用频率 × 驾驶安全相关性 × 热区可达性;附"考虑过但放弃"的替代方案(如按功能类别分组、为什么不如按频率)
  ⚠️ 重构出的依据必须是面试被追问时真能顺着讲的,不能是装出来的
- **决策 B|准入与去向**:什么功能配进控制中心、什么沉到设置页——把"产品让加"转写成"我定义了进入方式与呈现层级"
- **决策 C|车规约束**:盲操 / 瞥视、亮暗态、可达热区,专门一小节(加分叙事)

### 5. 结果
- 上线情况 + 可引用的用户反馈 / 验收评审结论(脱敏)

### 6. GAS 规范 × 自研框架融合(独立一节,2-4 页,反击"外包只做执行")
- 我负责主框架与开机引导的规范融合
- 写法待盘点(见待办):冲突案例(GAS 硬性要求 vs 品牌规范,谁让步、规则怎么定)、产出物形态、我的真实决策空间(主导 vs 深度参与,如实)
- 与案例②的暗线:两套规范下做设计 = 平台约束下做设计,和"车规约束下设计 Agent"同一种能力
- 若为出海车型:GAS/AAOS 合规经验同时写进简历关键词

### 7. ✨ LLM 延伸(差异化尾巴,直接接案例②)
- 核心问题:**"当 Agent 能听懂'我有点冷'时,控制中心还剩什么?"**
- 答案:不是消失,而是转型——从操作入口变成 **Agent 行为的可见层**:
  执行回显(Agent 调了什么)/ 当前状态 / 一键撤销 / 授权开关
  手动面板成为人对 Agent 的信任兜底
- 1-2 页概念稿,与案例②"Agent 授权边界"呼应但不重复
- 三案例咬合叙事:**① 我做过 Agent 要操作的工具层 → ② 我设计操作它的 Agent → ③ 我研究了用户什么时候肯放权**
