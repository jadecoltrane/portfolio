## 背景（脱敏）

- 现状：系统桌面的多任务能力靠**小窗**承载——两个小窗容器，普通小窗默认在左，横屏影像类小窗默认在右上、层级更高；
  小窗之间有「堆栈」（按调起时序排序）和「移栈」（用户关闭或业务自动清除）逻辑；另有临时小窗（盲区影像、语音、通话）
- 目标：参考小米等竞品，升级成**多窗口（视窗，1/3、2/3、3/3 比例）/ 多卡桌面 / 负一屏**的形态
- 同事已列了一份问题清单，覆盖：视窗是不是稳态桌面（单独形态还是副桌面）、1/3 窗是应用形态还是临时内容、
  视窗与现有小窗的关系、比例切换、打开应用与回到桌面的路径、widget 卡与视窗的关系、卡片按整屏还是逐卡滑动、整体时间计划

## 这一轮补的三个问题与方案（2026-10-21 草稿）

⚠️ **归属先写清楚**：下面的问题与方案是 jade 在对话中与 Claude 一起起草的**初稿**，
还没有在项目里提出，也没有被采纳。进作品集之前必须确认：**哪几条是她拍板提出的、团队最后采纳了哪个方案**。
只有她提出并推动落地的部分才能算作品。

### 问题 1：没有适配 1/3、2/3 形态的三方应用，在视窗里怎么显示？

| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 方案一：兼容模式 | 按手机竖屏比例渲染后等比缩放进视窗，空白处留黑边或模糊背景；角标标「兼容模式」，点击切 3/3 全屏 | 所有应用都能进视窗，不需要三方配合 | 显示效果一般，1/3 窗里字偏小 |
| 方案二：白名单分级 | 只有适配过的应用能进 1/3、2/3；未适配的直接全屏，拖进视窗时提示「仅支持全屏」；对外出适配规范 | 体验可控，不会显示错乱 | 初期能进视窗的应用少，靠生态推动 |

### 问题 2：盲区、倒车、通话等临时任务打断后，视窗的布局和状态怎么恢复？

| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 方案一：覆盖后原样还原 | 临时任务以浮层盖在视窗上，下面布局不变、应用后台运行；结束后浮层消失 | 实现简单，没有割裂感 | 浮层期间遮挡视窗内容 |
| 方案二：临时占用一个视窗 | 临时任务挤进离主驾最近的视窗，其他视窗缩小让位；结束后按记录的比例和应用自动恢复 | 不遮挡其他信息 | 布局频繁变动，对动效衔接要求高 |

### 问题 3：横屏影像类小窗和视窗同时存在时放在哪？

| | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 方案一：保持悬浮，四角吸附 | 延续现有逻辑，悬浮在视窗上层，默认右上，可拖到四角吸附 | 改动最小，延续用户习惯 | 遮挡下方视窗 |
| 方案二：画中画嵌入焦点视窗 | 变成画中画嵌在焦点视窗一角，随视窗缩放；点击展开成 2/3 视窗 | 少一个独立浮层，层级变简单 | 视窗为 1/3 时画面太小 |

## 被拿掉的一条，以及为什么

原本第一个问题是「行车中视窗能做哪些操作」（方案：行车全锁 / 行车简化操作）。

查公开资料后拿掉了：小米 SU7 首页卡片支持排序、拖滑块调大小、全屏、双卡与三卡分屏；问界支持导航与其他应用分屏、三指流转；
特斯拉限制的是行驶中看视频；**没有一家公开说行车中锁定布局**。行业做法看起来是「布局可调，限制落在内容上（主驾视线内不播视频）」。
全锁方案比竞品更严，会被用户嫌难用，所以整题拿掉。

这些资料多是 2024 年左右的评测，没有一份写明行车态规则；**要下结论得实车走查**（D 挡行驶中试拖分割线、改卡片大小、进编辑、开视频）。

## 这一轮纠正过的两个前提（写案例时可以用）

1. **「视窗」不等于「卡片桌面」。** 视窗里跑的是应用本身的窗口（可完整操作、可全屏）；widget 卡是轻量信息卡，点开才进应用。
   小米首页那三张「卡片」能调大小、能全屏，本质更接近视窗。
2. **「视窗」不一定是一个桌面。** 它是稳态主桌面、副桌面还是临时分屏，正是同事清单第 1 条还没定的事。
   上面三个问题刻意写成不依赖这个前提——只要存在 1/3、2/3、3/3 的视窗，它们就都成立。

这两条是「先定概念、再谈方案」的真实例子，以后写方法论时比方案本身更有说服力。
