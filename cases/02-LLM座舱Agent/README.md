# 案例② 车载语音助手 → LLM 驱动座舱 Agent 重设计（主力案例）

**定位**：整本作品集的核心证据——证明我能把 LLM 的开放理解与工具调用能力，转译成可授权、可解释、可恢复的座舱交互，而不只是画对话界面。目标读者：大模型公司与车企 AI 座舱团队。

## 选题

选择一个有充分公开实测素材、能够形成完整失败证据链的量产车载助手作为重设计对象。用户无实车，取证只使用公开评测、车主视频与官方演示，并记录来源、版本和获取日期。

## 核心结构：安全委托闭环

案例不再把五个 AI 命题平铺成知识清单，而是用一个端到端闭环串联：

1. **理解**：识别意图歧义，不把模型表达的信心直接当成正确率。
2. **提案**：将多步计划与等待过程转译为可理解的语音和界面状态。
3. **授权**：由确定性的策略层综合动作风险、车辆状态、用户授权和意图歧义，决定直接执行、确认、停车后继续或拒绝。
4. **执行**：动作有回显、有真相之源，可逆动作提供快速撤销。
5. **恢复**：断网、工具失败、理解错误和用户打断都有明确出口，手动操作始终可达。

## 可跑 Demo

- 技术：LLM API + 轻前端 + 模拟车控工具 + 确定性策略层。
- 范围：只做 3 个核心场景，覆盖正常执行、需确认、高风险拦截和失败恢复。
- 演示控制台里的歧义度、断网和车辆状态开关是**测试注入工具**，不伪装成量产系统能力。
- 代码放本目录 `demo/`。

公开失败证据 → 问题模型 → 安全委托闭环 → 三个关键场景 → 可运行 Demo → 系统化验证与局限
