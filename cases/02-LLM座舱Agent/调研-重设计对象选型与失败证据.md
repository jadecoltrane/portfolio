## 一、选型标准（源自 README 的既定要求）

1. 量产在售、公开实测素材充分（评测文章、车主视频、论坛帖），无实车也能取证
2. 能形成**完整失败证据链**：覆盖至少 3 类关键失败（理解错误 / 高风险误执行 / 无恢复路径）
3. 叙事张力：最好处在"命令式旧框架 + 正在接入大模型"的过渡态——重设计的必要性不言自明
4. 无敏感性冲突：与用户在职公司无可识别关联

**推荐结论：以比亚迪小迪为重设计对象。** 理由：公开素材全网最多（装机量决定）；交互框架是教科书式的"命令—执行"契约；且正处在接入大模型的过渡期——"新能力装进旧框架"的问题最典型。行业级安全证据（灯光事件）另行引用，不要求都发生在同一产品上，正文 1.2 的表本来就允许跨产品取证。

**⚠️ 敏感性提示（需你拍板）**：2026-02 灯光事件涉及具体品牌（领克 Z20/极氪/深蓝，均为公开新闻报道，引用不等于泄密）。若你不希望正文点名任何品牌、或担心面试中被顺势追问个人经历相关话题，可统一用匿名写法："多个品牌被公开报道的行驶中误关大灯事件"。**默认建议：匿名化写法保留这条——它是全表最硬的证据，正好证明"策略层不是过度设计"。**
