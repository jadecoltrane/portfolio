# 座舱 Agent · 安全委托闭环 Demo

验证的不是"模型有多聪明"，而是**安全委托闭环能否在正常、歧义、高风险和失败状态下稳定运行**。

## 运行

零依赖、纯静态。ES Module 需要 HTTP 服务（file:// 打不开）：

```bash
cd cases/02-LLM座舱Agent/demo
python3 -m http.server 8000
# 打开 http://localhost:8000
```

部署：整个 `demo/` 目录扔到任何静态托管（GitHub Pages 即可）。

## 机制测试

```bash
node --test cases/02-LLM座舱Agent/demo/tests/*.mjs
```

25 条测试覆盖 demo方案.md 第五节验证清单：授权（同一请求 × 不同车辆状态/授权档位）、歧义（缺参数/多候选先澄清不猜测）、恢复（断网降级/工具故障/失败后有出口）、一致性（回显=真相状态，撤销恢复原值）、确定性（同输入 100 次同输出）。**这是机制验证，不等同于真实道路分心测试或量产安全验证。**

## 架构与诚实性口径

```
浏览器（全部逻辑，无后端）
  ├─ nlu.js          理解层：规则引擎模式（默认）——确定性解析，如实承认能力边界
  ├─ llm-adapter.js  理解层：LLM 模式（可选）——接自有 Serverless 端点，key 不进前端
  ├─ policy.js       策略层：纯函数。动作风险 × 车辆状态 × 用户授权 × 意图歧义
  │                   → 直接执行 / 请求确认 / 停车后继续 / 拒绝（+ 澄清 / 断网降级）
  ├─ tools.js        模拟车控工具（含元数据）+ 车辆状态真相之源
  └─ app.js          交互层：语音按句播报、屏显按块更新、回显/撤销、行为记录
```

- 右侧**测试控制台**（断网 / 工具故障 / 歧义注入）是测试注入工具，不伪装成量产系统能力。
- 理解层可替换（规则 ⇆ LLM），**授权决策永远留在确定性策略层**——这是本案的核心主张，也是两种模式共享同一意图结构的原因。
- 行为记录展示每次请求的 请求 → 策略结果 → 理由 → 可撤销状态，以及"首个可理解反馈时间"指标。

## 面试官可以试什么

1. 点"场景 1"，执行后说**撤销**——纠错比重说一遍快。
2. 把授权里"空调"改为**每次确认**，再说"我有点冷"——同一句话进入确认流程。
3. 点**证据场景"关闭所有灯光"**（D 挡）——策略层拦截并给替代方案；切 P 挡再试，放行。对照 2026-02 多品牌"行驶中语音误关大灯"公开事件。
4. 场景 3：导航歧义澄清 → 付款被转"停车后继续" → 切 P 挡恢复任务。
5. 打开**切断网络**——云端检索降级说明，"我有点冷"（本地车控）不受影响。
6. 注入**工具执行故障**——失败后重试/稍后/放弃三选一，目标不丢。

## 启用 LLM 模式（可选，不影响机制演示）

部署一个转发端点（Vercel / Cloudflare Workers），契约见 `js/llm-adapter.js` 头注释，然后在 index.html 里加：

```html
<script>window.DEMO_CONFIG = { llmEndpoint: 'https://你的端点/understand' };</script>
```
