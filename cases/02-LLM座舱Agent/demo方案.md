# 案例② Demo 技术方案

> 2026-07-11 草案。目标:**能发链接、能录屏、面试官打开就能玩**的座舱 Agent demo,证明五命题的设计答案是可运行的,不是纸上谈兵。

## 一、技术选型建议:裸 API + 轻前端(不用 Coze/Dify)

理由:
- 目标读者含大模型公司面试官,**裸 API + tool use 更能证明你理解 LLM 应用的真实构造**(流式、工具调用、上下文管理),Coze/Dify 会被解读为"只会搭积木"
- 五命题里的流式节奏控制、置信度分档、失败注入,编排平台反而难做精细
- 代码量可控:一个前端 + 一个薄后端,Claude 代写大部分

架构:

```
浏览器(座舱模拟界面)
  ├─ 中控屏 UI:对话流 + 结果卡片 + 控制中心(Agent 行为可见层!)
  ├─ 模拟仪表条:车速/挡位(P/D 切换改变交互形态 → 命题四)
  └─ 演示控制台:断网开关 / 置信度拨盘 / 授权设置(面试官玩的地方)
        │ SSE 流式
后端(serverless,持 API key)
  ├─ LLM 调用(Claude API,streaming + tool use)
  ├─ 模拟车控工具集:set_temperature / navigate / find_poi / send_message / pay
  │   (每个工具带授权级别元数据 → 命题三)
  └─ 失败注入层:断网 / 超时 / 低置信模拟(→ 命题五)
```

- 前端:Vite + React(或纯 HTML/JS,以最快跑通为准),横屏车机比例
- 后端:Vercel serverless function(API key 放环境变量,免暴露)
- 部署:Vercel 免费档;链接放简历与 PDF
- 兜底:准备一份**录屏版**(demo 挂了/面试断网时用)+ 关键路径的"回放模式"(预录响应,不耗 API 也不怕抽风)

## 二、三个场景的实现清单(与正文第 3 节对应)

### 场景 1:"我有点冷"(最小闭环,先做这个)
- 语音输入用文本框+麦克风按钮模拟(Web Speech API 可选,不作依赖)
- Agent 调 set_temperature 工具 → 中控出现执行回显卡("空调 22° → 24°")+ 撤销按钮
- 控制中心面板同步高亮变化项——**案例①"可见层"概念的实机版**
- 变体:授权设置里把空调调成"需确认",同一句话走确认流程 → 边界可调的实证

### 场景 2:"找个能充电还能遛狗的地方"
- find_poi 工具返回模拟数据;演示多步规划(查桩→查周边→筛选)过程回显
- 流式:进行中状态逐步显示"正在查充电桩…";结果以整卡出现(块级更新)
- 中置信演示:置信度拨盘调低 → 同一句话变成候选确认式

### 场景 3:改行程 + 断网(D 挡)
- navigate 改道 → 口头确认级;pay(预约付款)→ 强确认级,必须点屏
- 演示控制台开"断网" → 显式降级声明 + 本地指令仍可用(温度/音量照常)
- D 挡状态下长列表自动折叠,P 挡展开 → 命题四实证

## 三、搭建排期(对应总排期 W1-W4)

- **W1**:场景 1 最小闭环跑通(前端骨架 + streaming + 1 个工具 + 回显/撤销)≈ 这周
- **W2**:授权系统(三级 + 设置面板 + 行为流水)+ 场景 3 确认流
- **W3**:场景 2 + 失败注入 + 置信度拨盘 + P/D 两态
- **W4**:打磨视觉(按车机规范:大字号、暗色、热区)+ 部署 + 录屏 + 回放模式
