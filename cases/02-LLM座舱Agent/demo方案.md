# 案例② Demo 技术方案

> 目标：做一个能发链接、能录屏、面试官打开即可操作的座舱 Agent Demo。它验证的不是“模型有多聪明”，而是安全委托闭环能否在正常、歧义、高风险和失败状态下稳定运行。

## 一、技术选型：LLM API + 轻前端 + 确定性策略层

理由：

- LLM 负责理解自然语言、形成候选计划和生成面向用户的说明。
- 策略层负责授权决策，规则必须可检查、可复现，不能依赖模型“自报有多确定”。
- 轻前端负责把流式生成、工具调用、车辆状态和失败恢复转译为可交互体验。
- Demo 只模拟关键机制，不假装具备真实 CAN 总线、驾驶控制和量产安全认证能力。

架构：

```
浏览器（座舱模拟界面）
  ├─ 中控 UI：对话、计划、结果卡片、执行回显、撤销
  ├─ 模拟仪表：P/D 挡、车速、网络状态
  └─ 测试控制台：断网 / 超时 / 意图歧义 / 用户授权
        │ SSE 流式
服务端
  ├─ LLM：理解意图、生成候选计划与工具调用建议
  ├─ 策略层：动作风险 × 车辆状态 × 用户授权 × 意图歧义
  │   └─ 输出：直接执行 / 请求确认 / 停车后继续 / 拒绝
  ├─ 模拟工具：set_temperature / navigate / find_poi / send_message / pay
  └─ 行为记录：请求、策略决定、执行结果与可撤销状态
```

- 前端：Vite + React（或纯 HTML/JS，以最快跑通为准），横屏车机比例。
- 后端：Serverless Function，API key 只放服务端环境变量。
- 部署：公开链接放简历与 PDF。
- 兜底：录屏版 + 关键路径回放模式；回放内容明确标注“演示数据”。

## 二、策略层：Demo 的核心证据

每个工具维护结构化元数据：

| 字段 | 作用 | 示例 |
|---|---|---|
| `reversibility` | 动作能否快速恢复 | 调温可逆，付款不可逆 |
| `safety_impact` | 错误是否影响行车安全 | 高速开窗高于调氛围灯 |
| `affected_scope` | 是否影响乘员或第三方 | 发消息会影响第三方 |
| `allowed_vehicle_states` | 哪些车辆状态允许执行 | 复杂支付仅限 P 挡 |
| `user_permission` | 用户当前授权上限 | 自动执行 / 每次确认 / 禁止 |

意图歧义不是让模型输出一个看似精确的百分比，而是由可观察信号构成，例如缺失必要参数、候选工具冲突、指代不明和用户表达与车辆状态矛盾。测试控制台可以直接注入这些状态，用于稳定复现确认和降级流程。

## 三、三个场景的实现清单

### 场景 1：“我有点冷”（最小闭环）

- 文本输入为基础，麦克风作为增强，不把浏览器语音识别当作核心依赖。
- Agent 提议调用 `set_temperature`，策略层判断为低影响、可逆、当前状态允许。
- 中控出现“22°C → 24°C”的执行回显和撤销按钮，控制中心同步更新真相状态。
- 变体：用户把空调授权上调为“每次确认”，同一句话转入确认流程。

### 场景 2：“找个能充电还能遛狗的地方”

- `find_poi` 返回演示数据，过程按“查充电设施 → 查周边条件 → 筛选”展示。
- 语音按句子播报，屏显按完整语义块更新，不逐字滚动。
- 注入“缺少距离偏好”或“多个候选并列”等歧义，让系统询问必要信息，而不是展示模型自报置信度。
- D 挡只给 2–3 个可瞥视候选；P 挡可展开完整列表。

### 场景 3：改行程、预约与断网

- 导航改道结合路线影响和车辆状态决定是否需要确认。
- 付款请求在 D 挡进入“停车后继续”，而不是通过更强弹窗允许驾驶员完成复杂操作。
- 注入断网后，系统明确说明能力边界；本地车控仍可用，云端检索与支付暂停。
- 执行失败时保留用户目标，提供重试、稍后继续或退出，不让用户从头重说。

## 四、搭建排期

- **W1**：场景 1 最小闭环（前端骨架 + 流式连接 + 1 个工具 + 回显/撤销）。
- **W2**：策略层、授权设置、行为记录和场景 3 的拦截流程。
- **W3**：场景 2、失败注入、意图歧义注入和 P/D 两态。
- **W4**：视觉打磨、脚本化验证、部署、录屏和回放模式。

## 五、验证清单

- 授权测试：同一请求在不同车辆状态和用户授权下，策略结果是否可预测。
- 歧义测试：缺少必要参数时是否先询问，而不是猜测执行。
- 恢复测试：断网、工具超时、用户打断和执行失败后是否都有下一步。
- 注意力测试：D 挡状态是否不出现滚动、复杂列表和需要连续点按的流程。
- 一致性测试：语音回显、屏幕状态和模拟车控状态是否一致。
- 响应节奏：记录首个可理解反馈时间、工具调用等待状态和撤销反馈时间。

验证使用固定的脚本化场景集，并在案例中如实说明：这是机制验证，不等同于真实道路分心测试或量产安全验证。

## 六、待定决策

- [ ] LLM 服务：优先选择支持流式与工具调用、国内演示网络稳定的服务；模型切换不作为首版范围。
- [ ] 语音：文本输入起步，浏览器语音识别只作增强。
- [ ] 部署：默认域名即可，不新增购买成本。
