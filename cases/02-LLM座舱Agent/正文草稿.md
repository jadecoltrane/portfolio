## 1. 为什么重设计:旧框架装不下新能力(2-3 页)

### 1.1 现有助手的问题不是"笨",是框架错了

传统车载语音的交互契约:用户说出**接近指令格式**的话 → 系统匹配意图 → 执行或播报失败。这个契约下,系统的一切 UI 都围绕"匹配成功/失败"二值状态设计。

LLM Agent 打破了契约的两端:输入端,用户可以说"我有点冷"“找个能带狗进的餐厅”这类**没有标准答案的话**;执行端,Agent 可以规划多步操作、调用多个工具、甚至主动建议。但公开可查的现状是:多数量产助手把 LLM 当成"更聪明的意图匹配器"塞回旧框架——听懂了更多话,交互上仍然是黑盒执行。

### 1.2 失败案例取证

【需素材:5-10 个现有助手的真实失败案例,全部来自公开渠道(B 站/抖音实测视频、车主论坛截图),标注来源。每个案例标注失败类型:理解错误 / 执行黑盒 / 不确定性掩饰 / 打断粗暴 / 失败后无路可走】

【配图 1:失败案例墙(公开素材脱敏拼图)+ 失败类型分布】

### 1.3 问题定义

> **当座舱助手从"命令执行器"变成"有能力但会出错的 Agent",交互设计要回答的不再是"怎么让用户学会说对的话",而是"怎么让人和一个不完全可靠的智能体在驾驶场景下安全地协作"。**

## 2. 五个命题的设计答案(10-12 页,核心章节)

### 命题一|不确定性表达:模型没把握时,UI 怎么办?(2 页)

**原则:置信度不展示数值,转译成交互形态。** 用户不需要知道"78% 确定",需要知道"它要不要我确认"。

三档降级机制:

| 置信状态 | 交互形态 | 例 |
|---------|---------|---|
| 高置信 | 直接执行 + 回显 | "已把温度调到 24°" |
| 中置信 | 先复述意图再执行(给打断窗口) | "你是想关空调对吗?3 秒后执行" —— 期间说"不是"即取消 |
| 低置信 | 转确认式交互,给 2-3 个候选 | "没太听清,你是想:A 调温 B 关空调?" |

关键设计点:
- **档位切换要平滑不突兀**:低置信不是报错,是换一种问法——语气与视觉上不制造"失败感"
- **驾驶中候选上限 2-3 个**,语音播报候选时屏显同步编号,方向盘按键可选
- **"宁可问,不可猜"的边界**:涉及行车安全与不可逆操作(见命题三)时,中置信也降为确认式

【配图 2:三档降级的界面状态图 + 一个完整流转示例】

### 命题二|流式响应:token 逐字吐出,驾驶场景怎么呈现?(2 页)

**原则:流式是技术事实,不是交互形态。驾驶场景下,"逐字蹦"对屏显是噪音、对语音是不可行。**

- **语音通道:句子级缓冲**——攒满一个语义完整的句子才开始播报,播报中后台继续生成;首句要快(目标 <1.5s 开口),后续靠播报时间掩盖生成延迟
- **屏显通道:块级更新**——按语义块(一个结果卡片、一个步骤)整块出现,不逐字滚动;驾驶中瞥视看到的永远是完整可读的信息
- **进行中状态**:Agent 在"想"或在调用工具时,屏显用轻量的行为说明("正在查充电桩…")而不是抽象 spinner——**让等待可解释**
- **打断**:用户任何时刻说话即停止播报(barge-in);打断后 Agent 保留已生成的上下文,不从头再来

【配图 3:双通道时序图(生成流 vs 语音播报 vs 屏显更新)】

### 命题三|Agent 授权边界:它能直接做什么?(3 页,与案例①咬合)

**原则:按"错了的代价"分级,而不是按"技术上能不能做"分级。**

三级授权:

| 级别 | 判据 | 例 | 交互 |
|------|------|---|------|
| 直接执行 | 可逆、影响小、纠错成本≈0 | 温度、音量、氛围灯 | 执行 + 回显 + 一键撤销 |
| 口头确认 | 可逆但打断成本高 / 影响他人 | 导航改道、给联系人发消息 | 复述意图,口头"确认"即执行 |
| 强确认 | 不可逆 / 涉钱 / 涉行车安全 | 付款、开车窗(高速中)、任何驾驶控制 | 屏幕点按或方向盘实体键,语音不可确认 |

关键设计点:
- **边界可感知**:授权设置页用同一张三级表呈现,用户能看到"它能直接做的所有事"
- **边界可调整**:每个功能的授权级别用户可上调下调,但**有底线**——强确认类不可降级(涉钱涉安全),这是系统立场
- **边界可追溯**:所有 Agent 执行记录进"行为流水",随时可查可撤销
- 与案例①的咬合:控制中心作为 Agent 行为可见层——回显、撤销、授权开关的常驻落点

【配图 4:三级授权表 + 授权设置界面 + 行为流水界面】

### 命题四|多模态与驾驶注意力:信息往哪放?(2 页)

**原则:通道分工按"驾驶时的注意力预算"分配,单次瞥视 <2s(NHTSA 分心指南口径:单次瞥视不超过 2 秒、任务累计不超过 12 秒)。**

- **语音**:结论与征询("已预约,充电桩在 3 公里外")——不播细节列表
- **屏显(中控)**:可瞥视的结构化结果(卡片、2-3 个候选)——驾驶中永远不需要滚动
- **HUD(若有)**:仅执行确认与导航类即时信息,一行以内
- **停车态解锁完整形态**:P 挡下才展开长列表、多轮比价这类高负荷交互;行车中主动折叠
- **Agent 主动发言的节制**:行车中主动播报仅限安全相关与用户订阅的事项;其余进"稍后摘要"

【配图 5:通道分配矩阵 + 行车/停车两态对比】

### 命题五|失败降级:失败体验是 AI 产品的第一体验(2 页)

**原则:每种失败都有明确的"下一步",用户永远不会站在死胡同里。**

| 失败类型 | 系统行为 | 用户的下一步 |
|---------|---------|-------------|
| 网络断 | 显式声明 + 降级到本地指令集(车控/媒体本地可用) | 常用车控不受影响 |
| 低置信/听错 | 转确认式(命题一) | 选候选或重说 |
| 幻觉风险(事实类回答) | 事实类信息标注来源;查不到就说查不到 | 不被错误信息误导 |
| 执行失败 | 回显失败原因 + 保留意图上下文 | "重试/换方式/算了"三选一 |
| 用户失去耐心 | 任何时刻方向盘一键退回手动 | 手动操作永远在 |

**手动兜底是安全网,也是信任机制**:用户知道随时能收回控制权,才敢把控制权交出去——这一点由案例③遗产(设计原则自检表)与案例①(可见层)共同支撑。

## 5. 局限与验证计划(1 页)

如实写,这是 HCI 训练的体现:

- demo 用模拟车控 API,没有真实车机延迟与 CAN 总线约束
- 没有真实道路环境的分心测评;若落地,验证计划:驾驶模拟器 + 瞥视时长测量 + NASA-TLX 负荷量表
- 授权分级的用户心智验证需要真实用户研究(什么算"影响大"因人而异)
- 大词不说满:这是一个"把问题定义清楚并给出可检验答案"的设计研究,不是量产方案
