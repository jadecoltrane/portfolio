## 里面到底有什么

旧作品集这几页讲的是同一件事的两个面：**一个播放中的内容，在多个音源和两块屏之间怎么分配、出错了怎么退。**

### 一、方控与音源逻辑（容错规则）

| | 规则 |
|---|---|
| 正常模式 | 方控依次切换蓝牙、USB、网络媒体等音源 |
| 异常模式 | 蓝牙未连接 / USB 未插入 / 网络异常 → **自动跳过该音源** |
| 异常模式 | 第三方应用未登录或未授权 → **提示但不播放** |
| 优先策略 | 系统默认回退至上一个可用音源，**保持播放不中断** |

配一张流程图：方控按钮 → 音源切换请求 → 当前音源可用？ → 可用则播放／不可用则跳至下一个 →
是否还有可用音源？ → 没有则保持当前播放。

她自己给这节写的结论句是：**「让每一次切换都在驾驶者无需思考的范围内完成。」**

### 二、主驾／副驾双屏协同（分配规则）

总逻辑写成了三个词：**互斥显示 ＋ 独立音源 ＋ 智能切换**。

| | 规则 |
|---|---|
| 主驾屏 | 聚焦导航、驾驶信息与音频播放；**行车中视频功能受限，控制按钮置灰**；副驾放视频时主驾自动切音频模式 |
| 副驾屏 | 独立显示多媒体，**行车中可继续放视频**；乘客连蓝牙耳机时音频只走耳机通道 |
| 协同 | 播放状态同步（暂停／播放／切歌）；**同一应用不在两屏同时显示**，避免资源竞争；**三指滑动在主副驾之间转移播放界面，播放不断** |

配图是两块屏并排的 Launcher 示意，带编号的 Tap 流程，标出了哪一侧在出声。

## 为什么这是一个案例，而不是又一个经历页

全书的主线是「我做的是系统级规则设计」。这套素材是这句话最直白的一份证据：
**它不是一屏界面，是一张别人能照着实现的状态机。**

和在册的几个案例不撞车：

| 案例 | 仲裁的是什么 |
|---|---|
| 案例⑤ 节日彩蛋 | **时间轴上的让位**——什么时候该打断用户 |
| 案例② 天气小窗 | **新形态进框架**——一个新东西在既有层级里怎么落位 |
| **本案** | **资源与通道的分配**——同一份内容在两块屏、多个音源之间归谁，以及**出错了怎么退** |

「容错」这一轴 v1 里完全没有。异常模式那四条（跳过、提示不播、回退、不中断）是整套素材里最值钱的部分，
因为它回答的是审稿人最爱问的那个问题：**这套规则在不理想的情况下怎么办。**
