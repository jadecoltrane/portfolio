## 新定位

**不是「多种窗口形态如何仲裁」，是「新功能怎么进入一套别人定好的框架」。**

框架的层级与仲裁规则不是她定的——那是约束。她的工作是：每进来一个新东西，
**为这个东西定它自己的规则**：它长什么样、待多久、什么时候必须让、怎么进怎么出。
这个主张比原来的「规则的仲裁」更小，但**每一条都站得住**，而且它恰好解释了
一个乙方设计师在量产项目里的真实位置。

| | 旧立案（作废） | 新立案 |
|---|---|---|
| 中心 | 主框架的窗口层仲裁规则 | 天气小窗（主干）＋ 无界应用的新增功能 ＋ E-call |
| 归属 | ❌ 主框架非本人主导 | ✅ 逐项主导，边界逐条写死 |
| 主张 | 规则的仲裁 | 在既有框架里为每个新东西定它自己的规则 |
| 篇幅 | 10–12 页主力 | **5–7 页短案例**（见下方「为什么不再是主力」） |

### E-call 要不要收回

E-call 是 2026-08-24 随旧案例② 一并移除的那项，**归属现已确认是她的**。

收回的理由很具体：它是**功能级的优先级仲裁**——紧急呼叫进来时谁必须让位。
这和主框架那套通用窗口层级规则是两回事：**后者不是她定的，前者是。**
所以把 E-call 写进来，不会把已经划出去的框架层又偷偷算回来。

⚠️ 但要避开一件事：案例⑤ 的主体就是事件仲裁（四级模型）。
E-call 在本案只能占**一个决策点**的篇幅，不能写成第二个仲裁模型，否则两案重复。

### 为什么不再是主力

「规则的仲裁」这条定位依附于主框架层，拿不回来了。而这条定位在 v1 里**已经由案例⑤ 承担**
（驾驶安全约束下的事件让位与四级仲裁），不需要再找一个案例去补。

形态定义本身是实打实的设计产出——职责边界、尺寸约束、可停留时长、能否被驾驶态打断、
怎么被拉起、怎么收回、结束后谁负责收尾——但它撑一个短案例合适，撑十页主力勉强。
**宁可做扎实的短案例，不要撑出来的主力。** 这和案例④ 降为经历页是同一条判断。

### ⚠️ 与案例⑤ 的重叠风险

案例⑤ 有一节是「载体分配与相对层级」（彩蛋该挂在挂件、全屏还是壁纸上），
与本案的「形态落位」是同一个动作在不同题目上的应用。两案同时在册时，
**本案要把重心压在「形态自身的定义」，把落位写成结论而不是方法**，否则读者会觉得看了两遍。

## ⚠️ 仍卡在你这里的一条

原来问的是「有没有两种窗口形态冲突、你定了规则解决的例子」——**那个问法已经作废**，
因为仲裁层不是你的。现在要问的是：

> **无界应用或天气小窗在落位时，有没有和既有形态撞过？**
> 比如小窗要出现时正好 Dock 在编辑态、无界应用要压住某个常驻区域、
> 两个小窗同时想出现——这类情况当时怎么定的，依据是什么？

- **有**：本案成立，按 5–7 页短案例写，这就是④ 站的主体。
- **没有**：靠天气小窗的多方案比选 + E-call 的优先级决策也能撑起④ 站，只是会薄一些。

**另外一条现在最值钱**：天气小窗那几套方案，**采纳的是哪一套、为什么是它、后来上线了吗**？
多方案比选加一个被采纳的结果，是标准 case study 最想要的那条线——
而且这是**全书目前唯一一处"我的方案被采纳"**（案例① 的提案尚无采纳结论，
案例④ 的改动不是她定的，案例⑤ 的结果她不声称）。值得问清楚。

保密边界照旧。

## 框架（草案，待上面那条确认后细化）

按 [排版规范.md](../../排版规范.md) 第 2 节的六站骨架。

- **① 概览**：Problem / Solution / Impact 三卡 + 角色边界条。
  **边界条必须写明：主框架与 FA 设计规范非本人主导，本案范围是无界应用与小窗两种形态。**
- **② 问题与约束**：既有框架已经定好了层级与仲裁规则，新形态要在这套规则里找位置——
  约束是别人定的，这正是这一站该放的东西
- **③ 研究与主张**：这两种形态各自要解决什么、为什么不是「再做一个小窗口」
- **④ 决策与规则**（主体）：职责边界 / 尺寸与停留时长 / 可被打断的条件 / 进入与退出路径。
  每条要有被排除的替代方案
- **⑤ 设计输出**：脱敏重绘的形态规范片段
- **⑥ 结果与反思**：上线与沿用情况
